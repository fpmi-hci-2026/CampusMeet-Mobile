# CampusMeet-Mobile (Мобильный клиент участника и сканер волонтера)

> **Лабораторная №4:** добавлены минимальный экран афиши `App.js`, конфигурация Expo, общий контрактный API-клиент и исполняемые тесты клиента. Билет, SecureStore и сканер остаются задачами ЛР7. Сборка на симуляторе в среде подготовки ЛР4 не запускалась.

### Проверка и запуск ЛР4

```bash
# Не требует установки Expo:
npm test
# Для запуска на устройстве:
npm install
EXPO_PUBLIC_API_URL=http://localhost:8000/api/v1 npm start
```

Сначала запустите API из CampusMeet-Server. Для iOS Simulator localhost указывает на Mac; для Android Emulator используйте `http://10.0.2.2:8000/api/v1`. Для телефона нужен доступный LAN-адрес компьютера и сервер, запущенный с `--host 0.0.0.0`; порт Docker по умолчанию привязан к loopback и для телефона потребует отдельной локальной настройки публикации. `EXPO_PUBLIC_API_URL` не является секретом; токены и ключи туда не помещаются. В `.env.example` дан шаблон. Контракт — OpenAPI из Server; тесты проверяют URL, обработку ошибок и несовместимого JSON. Полная установка зависимостей и актуализация Expo SDK относятся к последующей работе и здесь не заявлены выполненными.

## Project Name
**CampusMeet-Mobile** — нативный кроссплатформенный мобильный клиент экосистемы CampusMeet для участников мероприятий, спикеров и волонтеров стойки регистрации на iOS и Android.

## Description
CampusMeet-Mobile спроектирован для мгновенного взаимодействия в полевых условиях площадки мероприятия. Приложение обеспечивает офлайн-доступ к динамическому QR-билету с криптографической верификацией (HMAC-SHA256) при полном отсутствии мобильного интернета и Wi-Fi, высокоскоростное оптическое сканирование камерой смартфона волонтера, составление персонализированного расписания докладов («Моя программа») и получение приоритетных Push-уведомлений за 15 минут до начала выбранных выступлений либо при экстренной смене аудитории. Интерфейс адаптирован под жесткие условия эргономики: управление одной рукой на ходу (Thumb Zone) и автоматическое повышение яркости экрана при открытии билета.

## Installation
Подготовка окружения мобильного приложения для последующей разработки (Лабораторная работа №7):

1. **Клонирование репозитория:**
   ```bash
   git clone git@github.com:fpmi-hci-2026/CampusMeet-Mobile.git
   cd CampusMeet-Mobile
   ```

2. **Предварительные требования к окружению:**
   - Node.js 20+ LTS
   - Expo CLI (`npx expo`)
   - Мобильное приложение Expo Go на физическом смартфоне (iOS / Android) либо настроенный эмулятор

3. **Установка зависимостей окружения:**
   ```bash
   npm install
   ```

4. **Конфигурация подключения к API:**
   Параметры шлюза API настраиваются через переменные Expo:
   - `EXPO_PUBLIC_API_URL`: URL шлюза API (например, `http://10.0.2.2:8000/api/v1` для Android Emulator или `http://localhost:8000/api/v1` для iOS Simulator).

* **[CampusMeet (Основной репозиторий для документации)](https://github.com/fpmi-hci-2026/CampusMeet):** `git@github.com:fpmi-hci-2026/CampusMeet.git` — главный системный репозиторий, содержащий академические отчеты по курсу ПЧМИ (`docs/reports/`), результаты исследования аудитории (`docs/survey/`), спецификацию REST API, проектную документацию и базу знаний GitHub Wiki.
* **[CampusMeet-Server (Репозиторий для серверного приложения и API)](https://github.com/fpmi-hci-2026/CampusMeet-Server):** `git@github.com:fpmi-hci-2026/CampusMeet-Server.git` — серверная часть и REST API шлюз (FastAPI / Python) для бизнес-логики, управления событиями, схемы реляционной базы данных (`database/schema.sql`), криптографической валидации токенов HMAC-SHA256 и интеграции с внешними API.
* **[CampusMeet-Web (Репозиторий для веб-клиента)](https://github.com/fpmi-hci-2026/CampusMeet-Web):** `git@github.com:fpmi-hci-2026/CampusMeet-Web.git` — веб-приложение для организаторов мероприятий (администрирование, квоты, модерация заявок докладчиков CFP, конструктор тайминга и аналитика).

## Usage
### Проектируемые пользовательские сценарии мобильного клиента (Лабораторная работа №7)

> **Примечание:** Описанные ниже сценарии определяют целевые пользовательские потоки (User Flows) и правила эргономики мобильного интерфейса.

1. **Сценарий участника (Attendee Mode):**
   * **Просмотр афиши и запись в 1 тап:** Выберите интересующий митап или хакатон и нажмите *«Зарегистрироваться»*. Билет с уникальным криптографическим токеном мгновенно сохраняется в локальное зашифрованное хранилище смартфона (SecureStore).
   * **Предъявление билета на входе (Offline First):** Нажмите на плавающую кнопку билета в нижней части экрана. Экран автоматически повышает яркость на 100%, отображая контрастный QR-код. Интернет не требуется! На iOS доступна кнопка *«Добавить в Apple Wallet»*.
   * **«Моя программа» и напоминания:** Отмечайте звездочкой доклады, которые хотите послушать. Приложение пришлет звуковой Push за 15 минут до выхода спикера на сцену.
   * **Поиск команды на хакатон:** Размещайте свою анкету с тегами навыков (Frontend, ML, UI/UX) или вступайте в существующие команды в 1 клик.

2. **Сценарий волонтера стойки регистрации (Volunteer Scanner Mode):**
   * Переключитесь в профиле в режим *«Сканер волонтера»* (требуются права доступа к событию).
   * Направьте камеру смартфона на QR-код участника. Сканер считывает код менее чем за 500 мс.
   * Экран мгновенно окрашивается в зеленый цвет с виброоткликом (Haptic Feedback) и выводит имя и категорию билета гостя. Повторное сканирование того же билета сопровождается предупреждающим желтым сигналом *«Уже прошел в 16:42»*.
